# WebAuthn Server Buildkit project guidance

**Last context pass:** 2026-10-20. **Next routine context pass:** 2026-11-19.

## Start here

This public `aoneahsan/webauthn-server-buildkit` repository publishes npm package `webauthn-server-buildkit`. The separate public docs repository is `/home/ahsan/Documents/01-code/projects/webauthn-server-buildkit-docs` and deploys through GitHub Pages. This is a custom, framework-independent Node.js WebAuthn server library; do not describe it as a wrapper around another package.

## Security contract

Package `2.3.2` provides registration, authentication, attestation, encrypted sessions, storage adapters, and WebAuthn types. Treat challenge lifetime and single use, RP ID and origin checks, user-handle binding, credential counters, algorithm/key compatibility, constant-time comparisons, attestation trust, session encryption, and error classification as security boundaries. Never weaken a check for compatibility or log credentials, session material, attestation payloads, or secrets.

The package currently has no automated tests. `docs/REPORTED-ISSUES.md` records this as a high-severity gap. A cryptographic or verification behavior change is incomplete without focused regression assertions or an explicit recorded blocker. Open dependency and release decisions remain in that issue file.

## Repository map

`src/registration/` and `src/authentication/` own ceremonies; `src/crypto/` and `src/attestation/` own verification; `src/session/` owns encrypted tokens; `src/adapters/` owns persistence contracts. `docs/` holds developer and maintenance records; user documentation belongs in the separate docs repository. `dist/` is generated by tsup and never hand-edited.

## Working rules

Use Yarn for local work. Never install, import, vendor, or copy an owner-created client package, including `@perkforce/tool-kit`. This repository is public: ignore real environment files, keys, certificates, service credentials, archives, and local agent settings. Test fixtures must be synthetic and contain no production authenticator or user data.

Preserve ESM, CJS, and declaration exports, source-map exclusions, the Node engine contract, and framework independence. Storage adapters must enforce expiry and atomic challenge consumption where their contract requires it. Public claims must be traceable to source, the WebAuthn specification, or current command output.

## Verification and release

Run `yarn install --immutable`, `yarn typecheck`, `yarn lint`, `yarn format:check`, `yarn build`, and `yarn pack --dry-run`. Inspect both module formats and declarations. A new release requires a semantic version, security-focused verification appropriate to the change, tarball inspection, and registry verification.
